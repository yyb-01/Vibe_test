# 저장 확정 발사의 서버 탄환 처리

`HostSession::publish_fire`는 durable applied 결과에서만 점 탄환을 생성한다.
shotId는 기존 월드 거래 sequence다. 제출 전에 최대 512개의 공간을 예약하고
빈 슬롯을 확인하므로 한도 초과는 탄약 소비 전에 거절한다. Pending/실패는 발사하지 않는다.

소유 스레드가 `advance_combat(nowQ16, air, scene, rules)`를 호출한다. 시각은
발사 승인과 같은 unwrapped 60Hz Q16 기준이며 1 tick에 240Hz substep 4개를 진행한다.
같은 시각의 반복 호출은 이미 진행한 구간을 반복하지 않으며 역행 시각은 거절한다.
클라이언트가 끊겨도 대기 저장을 조회해 확정 발사를 한 번 공개한다. 저장 실패는 보관해
첫 원본 재시도에 반환한다. 재전송은 원래 결과를 돌려주며 탄환을 다시 생성하지 않는다.
대기 발사의 결과 조회는 세션이 소유한다. 외부 호출자가 먼저 abort 결과를 소비하면
세션의 실패 재전달을 보장할 수 없다.

`advance_shots`는 기존 자유비행·정적 AABB·승인 도탄 루프를 재사용한다. 전체 substep만
진행하고 6초/2.5km·substep 8회/수명 16회 접촉 한도를 유지한다. 이동과 접촉은
작업 복사본에서 계산하며 배치 실패 시 공개하지 않는다. 저장 확정의 공개는 이 계산과 별개다.
접촉 출력은 정확한 절대 시각, shotId, 접촉 순번으로 정렬한다. 사건 식별자는
world+shotId+수명 전체 접촉 순번이다. 정지/만료 탄환은 활성 목록에서 제거한다.

입력은 서버 내부 상태다. scene과 승인 profile은 호출 동안 불변이고 SurfaceKey 순서다.
도탄에는 명시적 gate가 필요하다. 한 배치의 모든 탄환과 따라잡기 구간에 같은 대기·profile을
적용한다. 현재 세션 탄환은 반경 0이며 탄약별 profile 선택·역사 rewind·관통 자동 진입은 남았다.
실제 게임의 권위 시계·관측/profile 공급자와 60Hz 호출 루프, 콘솔/UE 사격 UI도 남아 있다.

비행 상태는 세션 메모리에만 있다. 시작할 때 저장된 발사 이력의 최대 shotId를 복구하지만
과거 탄환을 재생하지 않는다. 재시작 중 비행 탄환은 복구되지 않는다. `ShotImpact`는 기하와
에너지 출력이며 영속 DamageEvent가 아니다. 피해·상처·사망·loot 저장과 사건 복구는 후속 범위다.

검증: `./scripts/build.ps1`의 발사 공개/실패/복구·배치 시험,
`./scripts/test-sqlite.ps1`의 실제 rollback·충돌·재시작 중복 방지와 Windows
TCP+SQLite 응답 유실·연결 해제·원본 재전송. 20인 전투 부하/엔진 프레임 예산은 미검증이다.
