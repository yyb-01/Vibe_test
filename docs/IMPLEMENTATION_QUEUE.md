## 진행 순서와 완료 조건

1. 기반 slice: 기존 인벤토리·SQLite·세션을 유지하고 TCP 실전송 검증을 마무리한다.
   UE 리슨 서버의 방 생성/참가/종료, 인증된 Pawn 관측, 메뉴와 저장 월드 선택을 연결한다.
   완료 조건: 방장 1+19인, 공동 상자, 연결 상실/재접속, 정상 종료와 crash 복구.
2. 전투 slice: 정수 탄도 reference, 충돌·에너지 장부, 조립·발사 승인과 역사 proxy.
   완료 조건: G.3 fixture와 scalar/SIMD parity, 원자적 탄약 소비, UE 사격/피격.
3. 차량 slice: 부품 질량·COM·관성, 휠·동력계, Chaos 차체, 운전 복제.
   완료 조건: G.4 질량 fixture와 차량 주행/충돌/탈락, 네트워크 조건별 보정.
4. 생존/제작 slice: wound·대사·섭취, recipe/escrow, 전력·열·소음, 작업대 파괴.
   완료 조건: 시간 분할 불변식, 원자적 소비/완료/취소와 정전·복구 보존 시험.
5. 월드 통합: 플레이어 합집합 활성 영역, 셀 pin, 구조·좀비, 지속 저장.
   완료 조건: 4×4km에서 20인 분산/밀집, 스트리밍 실패와 장시간 부하 시험.
6. 콘텐츠: canonical skeleton/socket, 에셋 validator, 승인 gold assets와 cook.
   완료 조건: F의 MUST 검사와 실제 아트 승인, 플랫폼 cook/성능 결과.

  정적 AABB 연속 충돌과 관통/도탄 에너지 장부도 구현했다.
  AABB 구간의 실제 이탈 여부·시각·법선도 반환한다. 내부 끝점을 출구로 취급하지 않는다.

  Q0.24보다 얇은 벽도 보존하며 출구 미확인 시 에너지 결정을 보류한다.
  자유비행은 Q0.24 잔여 시간 적분을 지원한다. 0·전체·절반·임의 비율을 검증했다.
  도탄 속도 응답과 예산 이하 속도 조정을 추가했다. 정지 충돌과 벡터 에너지 장부를
  통일했으며 승인된 정적 축 반사의 잔여 시간·반복 접촉 루프를 연결했다.
  substep 8회/수명 16회 한도와 0.1mm offset의 다른 장애물 정지를 검증했다.
  표면 이탈 질의가 직전 면의 바깥 방향만 억제하도록 확장했다. 같은 collider의
  다른 표면과 이탈 offset 안의 얇은 장애물은 계속 검출한다.
  자유낙하/등속/항력/바람/얇은 벽/에너지 보존 검증 통과.
  곡률 분할·정적 불투과 장애물·반경·6초/2.5km 제한을 실행 루프로 연결했다.
  넓은 정수 나눗셈과 `std::gcd` 약분으로 비용을 줄였다. [합성 측정](BALLISTICS_PERFORMANCE.md).
  정상 비행의 위치/속력 한계 초과는 명시적인 `Limit` 정지로 처리한다.
  도탄의 탄약 허용·입사각·재현 가능한 샷 난수 gate도 루프에 연결했다.
  에너지별 도탄 확률·유지율 표를 매 접촉에 연결하고 보정 범위 밖을 거절한다.
  관통의 진입 손실·감속을 반영한 통과 시간 계획과 절대 시각의 속도·거리·흡수량
  조회와 관통 상태 생성/재개를 추가했다. 출구 이후 잔여 시간을 반환한다.
  점 탄환의 관통 상태를 projectile 수명/거리 장부에 연결했다.
  출구 이탈·잔여 시간 비행/반사를 연결하고 출구 장애물과 접촉 한도 공유를 검증했다.
  겹친 layer 경로 조회·body hitbox 구간 합집합·순서별 에너지 계획을 추가했다.
  접촉 진입 선택, 이 계획의 시간 진행/피해 연결은 후속 작업이다.
  공중 접촉→관통 자동 진입·겹친 layer 시간 진행·국소 손상별 도탄 응답/거칠기·
  역사 proxy와 피해는 미연결이다. 발사 승인·탄약/내구도 저장은 아래 범위까지 연결했다.
  FireIntent 34B codec과 서버 snapshot 기반 후보 검증을 추가했다. 원격 200ms 총 보상,
  로컬 서버 시각, sequence wrap·역전, 수신 시각 기준 발사 간격을 검증했다.
  탄약/내구도/shot 데이터의 영속 커밋을 기존 요청 저장에 연결했다. 후보 검증의 실제
  authority 공급자, 무기 FSM·커밋 이후 피해 소비는 남아 있다. FireIntent의 HostSession
  진입점과 account/fireSeq 원본 조회, HostTransport TCP 분기와 ShotAccepted wire를 연결했다.
  ClientTransport 발사 추적/재전송과 승인 후 snapshot 갱신을 연결했다.
  HostSession이 계정 sequence·무기별 steady cooldown과 Pending 예약을 유지하고
  저장된 applied 발사에서 세션 시작 이력을 복구한다. 최소 간격 경계·rollback·clock reset 검증 통과.
  실제 1발 장전실 원장과 확정 전 위치 검사를 연결했다. 장전/급탄은 기존 Move/Split이다.
  혼합탄 탄창은 Slot.socketId 순서의 동종 스택으로 표현하며 상태값도 보존한다.
  SQLite에서 장전 rollback·응답 유실·재시작 후 급탄 순서와 발사 공동 복구를 검증했다.
  현재 탄창 한도는 32발이며 family/profile·소켓 호환·전체 장전 FSM은 아직 남아 있다.
  해당 컨테이너가 있으면 checkpoint v3를 쓰며 기존 v1/v2 읽기와 버전 변조 거절을 검증했다.
  저장 확정 발사를 `publish_fire`로 한 번 생성하고 `advance_combat`에서 240Hz로 진행한다.
  Pending/실패·연결 유실 중 확정·시간 역전·접촉 정렬·원본 재시도 중복 방지를 검증했다.
  현재 최대 512개 점 탄환이며 static 장면/대기/profile을 한 배치에 적용한다.
  비행 상태는 재시작 복구하지 않는다. [서버 처리 계약](../core/COMBAT.md).
  실제 관측·탄약별 profile·게임 호출 루프·자동 발사·시각 효과/영속 피해는 후속 작업이다.
- UE: 기본 경로/등록 정보에 설치 없음, 사용자도 미설치 확인.
